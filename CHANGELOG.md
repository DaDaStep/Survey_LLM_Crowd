## Format

Each release should list changes under:

- **Added** — new features, files, papers.
- **Changed** — changes to existing features.
- **Deprecated** — soon-to-be-removed features.
- **Removed** — removed features.
- **Fixed** — bug fixes.
- **Survey** — content milestones (e.g. outline agreed, draft submitted).

Use these version tags:

- `Unreleased` — work that has landed on `main` but is not yet a release.
- `v0.x` — pre-release milestones (e.g. `v0.1 — initial 30 papers`).
- `v1.0` — first submission.
